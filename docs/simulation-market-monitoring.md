# A 股与港股通模拟扫描和盘中监控

这套能力只做研究、模拟记录和人工复核提醒，不连接券商，也不会自动下单。
原有收盘分析与 20 个交易日模拟状态继续由 `00-daily-analysis.yml` 保存；新增
工作流不会重置该状态。

## 云端运行节奏

- `00-daily-analysis.yml`：交易日北京时间 18:00 为收盘分析和模拟记账的计划触发时间，
  支持 cron-job.org 外部 `workflow_dispatch`，保留 GitHub 原生 `schedule` 辅助兜底。
  外部任务需在该服务实际保存并启用，合并代码本身不代表外部配置已完成。
  GitHub 高负载时可能延迟甚至丢弃定时任务，18:00 不代表实际启动或完成时间。
  两入口共享原有 `stock-analysis` 串行组；收盘准入在恢复数据库和分析前检查同归属日
  已执行的任务，重复运行只上传审计，失败任务与rerun不能自动重做。GitHub API失败、
  截断历史或日期不明时拒绝进入生产；显式`trade_date`只能核对原始run归属日，不能
  覆盖时间窗。外部收盘也保留19:27收盘扫描兜底，重复入口不会重复产生扫描或记账。
  验收须核对原始创建时间、实际提交、归属日、PRIMARY覆盖及产物，不能只看绿色状态。
  调度语义参见 [GitHub schedule 官方说明](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。
- `01-intraday-session.yml`：外部 cron-job.org 仍是主要精准触发源，在交易日
  北京时间 09:20 以 `workflow_dispatch` 触发 `session=morning`，12:50 触发
  `session=afternoon`；GitHub 原生 `schedule` 使用相同时间作为辅助兜底。三类入口
  都先经过交易日、目标时段、迟到窗口和 `trade_date + session` 幂等占位，重复触发
  只会留下安全跳过审计，不能重复产生交易信号。GitHub Actions 页面仍可用 Run
  workflow 手动选择 `auto`、`morning` 或 `afternoon`。每个连续监控时段正常约
  60 秒取一次基础实时行情；A 股使用腾讯批量行情，港股在配置 Longbridge 凭据后
  优先使用带最新成交时间戳的授权 L1 批量行情。港股连接建立时验证 OpenAPI 港股
  个股实时权限，每轮验证本次快照拉取和逐只提供方时间戳；最新成交时间超过交易新鲜度
  阈值时，实时链路仍可保持健康，但该价格不会触发买卖建议。价格临近风险位或
  条件位时约 30 秒一次，数据源降级时放慢到约 120 秒。腾讯港股延迟行情只保留
  为诊断证据，不会被放宽新鲜度后用于买卖判断。每次未取消且至少一个市场为交易日的
  盘中 Actions 都会强制执行 Longbridge、PRIMARY、交易日历和 PushPlus 严格验收，
  证据不完整即失败；A/H 均休市时生成 `market_closed` 审计报告并正常结束，不启动
  行情循环和扫描 watchdog。
- `03-intraday-supervisor.yml`：独立于分钟监控的顶层轻量 watchdog。北京时间
  09:28/12:58 检查相应 `01` 是否已 queued、running 或 completed；安全补跑窗口内
  没有对应任务时，以 `trigger_source=supervisor` 自动 dispatch。10:16/13:46 再做
  过时检查；超过上午10:15或下午13:45绝不补交易信号，只发送一次可重试且去重的
  PushPlus `SYSTEM` 调度故障告警。GitHub Actions 查询或 dispatch 失败同样写入完整
  诊断并主动告警。它负责保证 `01` 活着，而 `01` 内现有 `market_scan_watchdog.py`
  继续保证 `02` 活着，形成两层容灾。
- `02-market-scan.yml`：北京时间 10:30、14:30 和 19:15 分层扫描 A 股全市场与
  港股通成分。全市场阶段不调用模型；只对规则短名单加载历史，再让通义千问和
  DeepSeek 独立复核。A 股快照按东财、腾讯、Sina 三条独立路由重试和降级；港股通
  成分接口异常时，会先使用独立保存且仍在有效期内的已验证成员集合批量取得腾讯
  提供方时间戳可验证的新鲜报价，再降级到全港行情并按成员集合过滤，不会把
  非港股通标的混入。A/H 两个市场独立隔离：一个市场不可用时只封锁该市场，另一市场
  仍可完成双模型复核和条件买入计划；整轮会标记为 `degraded` 并接受严格门禁检查。
  上午和下午的盘中长任务会在 10:42、14:42 检查对应扫描是否漏跑，18:00 收盘任务
  会在 19:27 检查收盘扫描；缺失时只补触发一次。原任务与兜底任务共享时段账本和
  concurrency，同一时段成功后不重复执行，超过最晚边界则只记审计、不追补旧行情。
  上午/下午 watchdog 会继续等待该时段扫描成功产物，只从固定名 artifact 安全读取
  `data/market_scan/latest.json`，校验模拟契约、时段和生成时间后原子更新盘中候选文件。
  下载时 GitHub 鉴权头仅发送给首次 API 请求，不随重定向转发给签名存储地址，避免
  存储端将 GitHub Token 误当作自身凭据而返回401；临时下载失败仍在现有期限内重新
  取得签名地址后重试，不能用旧文件冒充本时段同步成功。扫描失败时同步诊断会保留
  失败的 run ID 与结论，仍给刚触发、尚未出现在 API 列表中的任务留下等待窗口。
  扫描或同步属于独立买入子链：失败时记录为 `degraded` 并停用本时段新候选热加载，
  但不会把已经通过行情与 PushPlus 严格验收的分钟主监控误判为失败。`02` 自身失败
  由其既有通知状态负责；GitHub API、dispatch 或产物同步等 watchdog 自身故障则由
  `01` 发送去重的 SYSTEM 故障/恢复通知，通知失败只记入独立状态且不改变主链结论。
  分钟循环按 `generated_at` 与内容指纹热加载：相同内容不重复，旧版本不回滚；更新的
  可信扫描即使候选为零也会清除旧候选，损坏或不可信的新文件会 fail-closed 清空扫描
  候选及待发买入事件，固定观察层保持独立。
  watchdog 与扫描时段护栏都会先按交易所日历分别判断 A 股、港股：两边均休市时
  直接记为 `market_closed`，不抓行情、不调用模型、不发送 PushPlus；仅一边休市时
  只扫描开市市场。日历不可用会明确标记 `calendar_degraded` 并保守继续，让既有
  行情新鲜度和数据质量门决定是否可用，避免日历故障静默漏掉真实交易日。
- `04-longbridge-preflight.yml`：手动、只读检查 Longbridge OAuth 行情包与港股
  提供方时间戳；该工作流不注入 PushPlus，不创建交易上下文，也不下单。

既有 cron-job.org 请求只传 `session` 与 `max_cycles` 也保持兼容，不要求改 URL、时间
或 Token；若要让 Actions 标题明确显示来源，可在上午/下午两个 JSON body 中分别追加
`"trigger_source":"cron_job_org"`。`trade_date` 保持省略或 `auto`，不要写死日期。

外部触发和 GitHub runner 仍可能排队，因此这些时间不是交易所级低延迟保证。任何
超过
90 秒、缺少时间戳或关键字段不完整的最新成交价，都不能触发交易类人工复核提醒。
Longbridge 官方字段中的 `timestamp` 是“最新价格时间”而不是响应生成时间；已验证
实时权限且本次成功返回的快照，若只是因为标的没有近期成交而超过 90 秒，会单独
记录为“无近期成交快照”，不冒充可交易新鲜价，也不误计为行情接口降级。
若 dispatch 到达时超过对应安全补跑窗口，入口会先于私密状态恢复、行情抓取和信号
生成执行 fail-closed 跳过；若已启动的旧入口直到原定交易时段结束后才进入分钟脚本，
系统仍会保留上午/下午的原始审计身份、
保留最近有效状态、记录 `late_schedule_skipped`，并通过可重试 outbox 发送该时段的
能力提醒；不会把迟到的上午任务改写成下午任务，也不会回填或伪造已经错过的盘中
行情。GitHub 任务摘要会明确标记“未执行”。触发迟到不能被解释为盘中监控成功；
若需要有服务等级保证的实时监控，必须迁移到持久云端运行器或合法行情商的实时
推送服务。

### 收盘外部定时入口与缺跑告警

沿用已配置盘中任务的cron-job.org账户、POST和既有GitHub鉴权，不在仓库或报告保存令牌。
新增三项工作日任务，时区Asia/Shanghai；现有上午、下午四项无需修改：

| 时间 | Actions工作流 | inputs |
| --- | --- | --- |
| 18:00 | `00-daily-analysis.yml` | `mode=full`、`force_run=false`、`trigger_source=cron_job_org` |
| 18:08 | `03-intraday-supervisor.yml` | `session=close`、`trigger_source=cron_job_org_supervisor` |
| 19:46 | `03-intraday-supervisor.yml` | `session=close`、`trigger_source=cron_job_org_supervisor` |

三项请求的body均为`{"ref":"main","inputs":{...}}`，URL沿用GitHub工作流dispatch接口，
仅替换工作流文件名。18:08检查原入口是否真实形成run；缺跑且未超过19:30时只补请求一次，
固定携带归属日且不force。补请求同时发送真实SYSTEM缺跑通知，不能宣称分析已经完成。
已有queued/running任务不再派发；失败或取消只告警，不重新分析。19:46检查完成、排队超时、
运行超时和晚窗缺失；超过19:30不再补请求。两市场均休市时正常跳过，日历/API无法确认时
告警并拒绝补跑。原生Supervisor增加同样两个检查时间，并按原始run创建时间处理跨午夜。
告警复用现有Supervisor状态缓存/备份、去重和失败重试；不会发送测试PushPlus。

外部任务启用服务自带的HTTP失败通知，可在GitHubdispatch接口拒绝请求时独立告警。
如果GitHub接受请求但整个Actions执行平台停摆，托管在Actions中的Supervisor也可能不能
及时执行；HTTP204只证明请求已接受。这一边界不能冒充端到端完成或实时告警保证。
新收盘产物的生产验证仍必须检查全部开市PRIMARY的同日收盘价、分析与有效参考位覆盖。


## 决策规则

监控频率和交易频率彼此独立。系统可以频繁观察，但只有当候选在扣除手续费、
税费和滑点后，预期风险收益比与年化效用明显优于现有方案时，才允许产生人工
复核事件。报告可安全推送不等于候选可交易；全市场候选还必须逐只满足完整深研、
双模型一致、无硬风险、进入新鲜有效价格区间等条件。

分钟循环只使用确定性规则、最新可靠行情、已落盘的止损/目标、可信候选计划和
模拟持仓，不在每轮新增大模型调用。`sharp_rise`、`sharp_drop`、`stop_loss`、
`target_reached`、adaptive、数据质量、信号时间、行情时间、价格、原因和决策结果
仍完整留账，但原始事件不会未经决策加工直接推送。

用户端 Push 只回答“现在怎么办”：仅当操作建议改变、风险实质升级、有效
突破/跌破新的可靠关键位、相对上次显著恶化、风险解除后重新触发，或新可靠计划
替换旧计划时发送。普通涨跌阈值触发但最佳动作仍为“不操作”时不推送；冷却时间
届满本身也不会机械重发。推送中的买入、加仓、减仓、止盈和止损均给出当前价格、
建议数量或仓位比例、触发价、委托参考价、失效条件、有效期、可靠依据、下一触发
条件和数据质量；下单仍需人工确认，系统不会连接券商。没有可靠资金与仓位尺寸的
候选观察只留审计记录，不冒充可执行买入建议，也不编造持仓、成本、Level-2、资金、
新闻或盘口。

数据覆盖不足只有在连续多轮且已经影响决策可靠性时推送一次降级提醒；同一故障或
部分降级状态不重复刷屏，可靠行情恢复后只推送一次恢复通知并清除告警状态。扫描
报告会分别写明 A 股、港股通的可用状态、来源、抓取时间、提供方时间和阻断原因，
不会因一个市场故障把另一个市场的事实误写成“快照不可用”。港股通成分来源与
报价来源分栏记录；研究快照可用不等于盘中新鲜报价，任何建仓仍须通过分钟链路的
新鲜 L1 复核。仅观察名单增删而 `actionable_count=0` 时仍保存报告和历史，但不发送
“候选变化”PushPlus；可执行候选新增、撤销或关键计划实质变化仍会推送。

港股通定向腾讯备用只接受90秒内且带提供方时间戳的正价格、正成交量和正成交额；
陈旧、缺时间戳或缺成交数据的标的会从本轮候选中排除，并记录请求数、新鲜覆盖数和
主/备用入口统计。该链只复用仍在840小时硬有效期内的成员代码，不会自行扩展港股通
范围，也不会用新报价延长成员资格缓存。两条腾讯入口和全港报价都不可用时，仍按原
规则尝试6小时内的最后良好快照，之后封锁港股通买入侧。A/H 跨市场隔离保持不变。

全市场扫描会在最终最多12只进入双模型前，逐只主动补充项目当前可取得的基本面与
事件/新闻证据，并将来源、抓取结果和缺失项一并交给模型；普通新闻不会冒充交易所
公告，仍未取得的政策、资金、盘口和授权 Level-2 也不会被推断或编造。规则过滤、
完整价格计划、扣费后风险收益、数据质量和千问 + DeepSeek 均通过时，候选按普通、
强、极强机会进入2.5%–10%动态仓位档。若恰好一方 `pass`、另一方仅明确标注
`non_critical_data_gap` 而 `watch`，且补证据已经实际尝试、没有任何硬风险或 reject，
只允许进入普通机会2.5%最低档；其他模型分歧仍全部观察。只有分钟监控取得新鲜行情、
价格进入买入区，并继续通过止损、扣费后风险收益、现金/单股上限和人工确认门禁，才
发送模拟建仓或加仓建议。每份报告展示“全市场输入 → L1 → 历史/计划 → 补证据 →
双模型 → 可建仓”漏斗及逐层淘汰原因；没有候选是正常结果，输入为零则是运行故障。

研究补证与双模型请求故障独立记录。扫描研究不再复用 AlphaSift 的固定4秒轻量
工具预算或 DataFetcherManager 的共享超时线程池：估值优先复用本轮已取得的扫描
字段（保留来源和抓取时间，不充当交易报价），财务沿用 AkShare/yfinance 适配器。
每个 AkShare 财务接口、每个已配置新闻 provider 以及公告索引请求都在可终止的
Linux 子进程中执行；请求设置 connect/read 超时，SDK总耗时由父进程deadline限制，
超时后强制回收进程及其进程组，避免遗留工作占满线程池。仅临时网络/限流错误
有限重试，超时后进入下一来源；请求始终受现有基本面阶段预算、单候选30秒、
研究阶段300秒及整轮预算共同限制。其他分析入口和 AlphaSift 工具行为保持原样。
不支持进程隔离的平台明确记录 `IsolationUnsupported` 数据缺口，不回退到无限等待。

只在同轮内复用成功的研究缓存，仍受 `FUNDAMENTAL_CACHE_TTL_SECONDS` 限制；
缓存命中保留原抓取时间和缓存年龄，失败结果不缓存。A/H公告优先用巨潮官方HTTPS
精确代码检索取得orgId；A股只接受六位代码完全相同且category为“A股”的记录，港股
只接受五位代码完全相同且category为“港股”的记录（例如02331不得混同002331），不以
公司名、近似代码或其他证券类别替代。该检索失败时按原阶段剩余预算读取既有对应
市场的官方HTTPS代码表备用；同代码存在多个orgId时直接拒绝，不以备用绕过身份冲突。
精确身份与代码表均缓存在采集器父进程，同轮按原TTL复用；代码不存在或
映射冲突明确失败，不降级为公司名或无范围搜索。索引按该股票身份只请求最新一页
（最多30条），不重复请求第一页或遍历全部分页。`query`保留日期范围、来源、总条数、
`has_more`及`latest_page_sample`覆盖声明，不能据此宣称全部公告均已取得。只有代码、orgId、官方文档域名、有效发布时间
和查询时间窗均通过的条目才能进入证据。公告索引始终标注 `content_reviewed=false`，
不能表示已审阅原文，更不能以普通新闻替代正式公告。SearXNG 实例发现和逐实例请求
分别受同一新闻阶段预算约束；首实例挂起后仍可切换，实例池缓存保留实际刷新时间及
失败退避，实例轮换在父进程保留。新闻保留现有日期/关联性过滤，
成功但零条有效结果记 `no_results`，与 `provider_error`、`NotConfigured`、超时分开。

漏斗新增研究 `attempted/complete/partial/unavailable` 及基本面、新闻、公告索引
有效覆盖。旧 `research_available_count` 为兼容保留，明确只指“至少有一块非空证据”，
不代表完整；只有状态明确为 complete 且三块都有有效证据才计完整。全空字段、
单纯状态包装和日期元数据不算有效证据。逐候选保留阶段、代码、来源、耗时、尝试
次数、预算、异常类别和原始缺口。研究取数错误使用稳定的维护预警指纹；预警和
恢复各通知一次，发送失败保留重试状态，不影响双模型完整性或盘中主链健康判断。
全部交易安全门、数据质量权重、双模型/条件共识和人工确认规则保持不变。

2026-10 研究备用补齐：行情快照缺少 PE/PB 时，只为候选查询东财逐标的估值及
百度 A/H 估值备用，不重抓全市场；保留数据日期、每字段来源、抓取时间、缓存年龄，
数据日期受现有研究时效窗口限制，不充当盘中交易价格。有效估值沿用既有质量权重，
不调整质量门槛。财务重复指标按位置读取，同名冲突留缺口；绝对收入/利润不能误取
同比增速，万元/亿元明确换算为元。备用只查询指定公司及最近年份，按最新非未来
报告期排序，只合并同一报告期字段，保留逐字段来源。港股 info、收入表、现金流表
独立隔离和缓存，避免一项超时丢弃全部证据；季度/TTM/比率标注各自依据和期间，
扫描不使用季度收入与TTM利润率推算净利润，也不把现金流的期间冒充收入表期间。

公司新闻备用仍使用既有新闻时效、相关性和内容过滤，行业匹配不能冒充公司新闻；
原搜索故障与备用无结果/恢复分别保存。官方公告正文只访问经代码与发布时间核验
的官方 HTTPS 文档，拒绝重定向和超过2MiB的文件，最多提取前三页2000字符，
正文须再次匹配公司身份；此摘录仍标注 `content_reviewed=false`，不是全文审查。
巨潮索引返回的 HTTP/HTTPS 详情页不直接作为正文请求：仅接受官方固定详情路由，
核对链接中的股票代码、唯一公告编号与索引发布时间后，转换为官方静态 HTTPS PDF。
原索引链接保留在 `url`，实际成功读取的 PDF 记录在 `document_source`；转换不发起
HTTP 请求，不增加请求次数或研究预算，PDF 缺失、身份不符仍保留正文缺口。
正文不可得时保留索引和明确错误，不隐去缺口；扫描总体研究继续为 partial 或
unavailable，不因新增数个字段标为 complete。漏斗 `research_field_coverage` 分别
统计估值、日期、财务字段及正文摘录，逐候选 `missing_fields` 留下具体缺口。
所有请求仍受 PR #28 的进程回收、请求/阶段/单候选/整轮预算和有限重试约束。
公告索引完成后的最后一次PDF读取不再为不存在的备用步骤预留一半剩余时间；
它最多使用原单请求上限与原阶段剩余时间中的较小值，仍受单候选总预算约束。
索引取数超时、正文超时与文档校验拒绝保持分别记录，此调整不代表远端正文已恢复。

每批请求通过现有可终止子进程执行，落实120秒墙钟截止，超时后回收进程组再按
原策略重试或使用同通道已配置备用模型；不以SDK的读超时替代硬截止。每模型480秒
总预算、外层540秒保护及全部数值/候选完整性门禁保持不变。研究执行器原4秒网络
上限保持；模型工作进程沿用其自身请求预算，不套用研究4秒上限。不支持fork的平台
明确失败关闭，不回退为不可回收的线程。逐请求记录预算、耗时和终态，不保存密钥或原始错误体。
公告正文护栏的具体原因（非PDF、超大小、重定向、身份不符、日期不符等）跨进程保留，
不再统一折叠成ValueError；此诊断改进不改变正文准入条件，也不证明远端正文已恢复。
索引被拒行保留有界原字段和拒绝原因；PDF正文区分文本不足与身份不符，并在原产物
保留文档来源、SHA256、字节数、提取字符数及最多1600字符头部摘录，跨隔离进程传回。
拒绝行和被拒PDF头部仅留在验收产物；发给双模型的两处公告证据及研究诊断会移除
这些原字段，保留错误类别和数据缺口，避免把不匹配公司的内容带入复核。
港股PDF头部带“股份代號/股票代码”明确标签的省略前导零代码也可核验；正文中的
任意金额、其他股票代码仍不能通过身份核验。这些摘录仍不表示全文审阅。
腾讯备用路由在`route_stats.rejections/rejected_quotes`保留逐只拒绝原因、提供方时间、
抓取时间和延迟秒数，区分缺价格、缺时间、未来时间、陈旧时间与请求失败；会话
`integration_verification.tencent_route_rejections`累计原因计数。此改动不调整90秒
新鲜度门槛，也不把约15分钟延迟的港股报价提升为可执行行情。

盘中候选事件的 `data_quality` 表示已通过既有新鲜度校验的行情状态 `fresh_l1`；
数值型研究评分独立保存在 `research_data_quality`，仍按原规则参与策略与置信度计算。
不得把研究评分当作行情状态交给交易门禁。旧版已因这一类型混淆被拒绝、且未形成
决策的同计划事件，仅在当前行情与计划重新通过全部原门禁时重评；保留计划指纹、
现金/仓位/去重和人工确认要求，不恢复旧通知、不重放旧行情。

双模型结构化复核各自按最多4只一批请求，保留每只完整的输入证据。每批主模型最多
尝试2次；主模型仍因超时、连接、408/429、临时5xx、LiteLLM响应转换、返回截断、空内容、
非法JSON或候选代码缺失/重复而失败时，最多再尝试同一提供方配置列表中的第一个备用模型
1次。只重试失败批次，不重跑已完成批次；每次请求最长120秒，每个模型通道整轮仍共用
480秒硬预算。鉴权、参数等永久性4xx不重试。SDK 内层重试关闭，避免多层重试叠加。
千问不会用 DeepSeek 代替，DeepSeek也不会用千问代替；有效的 pass/watch/reject 不重试，
不以重试改变既有否决。任何一批最终失败都不会把部分结果当成完整复核，也不能因此进入
受限2.5%档；另一方仍独立复核，最终沿用原有失败告警和买入拦截。
`diagnostics.llm_calls` 保留逻辑复核次数，`diagnostics.reviewer_requests` 逐模型、逐批次
记录主备身份、重试次数、完成数量、耗时及脱敏错误码，不保存密钥、请求正文、完整模型原文
或原始错误体；仅数值矛盾附带有界原句语境用于诊断。研究数据不可用单独记录为 data gap；只有模型请求、结构化输出或批次
完整性失败才标记复核故障。任一批次最终不完整仍保持 fail-closed。
这些恢复参数随代码生效，无需变更 GitHub Variables 或 cron-job.org 配置。回滚时
revert 本次修复提交即可；既有候选状态与通知账本不需要重置。

## 死拿与策略影子账户实验

实验以 2026-08-07 收盘为冻结时点，从下一个交易日开始比较用户确认的 14 只核心
持仓；被明确排除的微小持仓不计入。A 账户 `buy_and_hold_baseline` 永久保持冻结
数量，只按可靠收盘价更新净值。B 账户 `strategy_shadow_portfolio` 从完全相同的
持仓、初始净值和零现金出发，只执行实验开始后实时产生并立即落盘的明确模拟决策；
卖出现金留在账户内，后续只有新有效买入/加仓信号才可使用。

策略影子账户把股票仓位 75%–85%、现金 15%–25% 作为常规目标带，而不是禁止优质
机会使用资金的绝对边界。现金已经达到或超过25%时，普通目标位止盈不再继续机械
减仓，而是明确提示“建议不减仓，继续持有”；硬止损和确定性风险退出始终优先，
不受现金护栏阻断。

买入侧按同一套确定性证据分级：普通机会的现金软底线/单股上限为15%/15%，强机会为
5%/35%，只有全市场技术排名前三、数据质量不低于0.80、扣费后风险回报比不低于2.0，
且千问与DeepSeek置信度均不低于0.90的极强机会，才允许现金最低接近0%、单股最高
接近50%。仓位增量同样分级：普通机会首笔/加仓为2.5%/2.5%，强机会为5%/5%，极强
机会首笔为10%、后续每次加仓为5%。若推荐档位受剩余现金或单股上限约束，系统会按
10%→5%→2.5%自动降一级，而不是因固定档位直接错过仍可承受的机会。每次加仓都必须
来自更新的一轮可信扫描；完整双模型一致时按原机会分级，只有上述“一方通过 + 非关键
数据缺失观察”的窄例外会被强制限制在普通2.5%档。当前价格仍不得低于该持仓的实验基准价。
所有档位都会先扣除待执行买入预留与成本，不允许现金为负，也不会放宽计划止损。
旁路观察账户没有可信的完整现金/NAV时不会套用 PRIMARY 现金比例，也不会把其数据
写入 PRIMARY 实验。

历史成本仅用于展示用户历史浮盈亏，不作为实验收益起点。两账户以冻结日可靠收盘
市值建立相同初始净值；正式 NAV 统一折算为人民币，其中港股在整个 20→60 日实验
永久使用 2026-08-07 基准汇率 `1 HKD = 0.8865 CNY`，不混入后续汇率波动。原始
CNY/HKD 分项和旧 1:1 口径只保留审计。策略账户采用统一人民币模拟购买力，A 股与
港股通卖出所得可跨市场再配置，不模拟真实港股通清算时差，也不允许现金为负。
比较中扣除显式标记为 simulation assumption 的手续费、税费和滑点。A 股新买入与
加仓按 100 股整数手；卖出和清仓可处理已有尾数。没有可靠港股每手 metadata 时不
猜测，并明确标记 `HK board lot not modeled`。信号账本只追加不回改；模拟成交使用
信号以后第一笔满足新鲜度要求的
可验证行情。`scheduler_missed`、`data_unavailable`、`stale_quote` 或
`execution_missed` 均不补单，也不记为策略主动不操作，避免前视偏差。

每个交易日收盘生成“死拿 vs 策略”私密成绩单，以扣费后的策略超额收益为第一
指标、两账户最大回撤差为第二指标，并分别展示现有持仓管理与新候选选股贡献。
第 20 个交易日只做第一阶段检查，不停止也不重置；同一状态自动继续至第 60 个
交易日完成首轮正式评估。整个实验只做模拟和人工复核，不连接券商、不读取券商
账户、不生成委托，也不使用真实资金。

由于仓库公开，14 只持仓的真实数量、历史成本和绝对净值不会写入源码、公开报告或
明文 artifact。初始化完成后 PRIMARY 只允许从 AES 加密状态恢复；cache 与 artifact
都无法恢复时直接失败，初始持仓 Secret 也不得用来重建。私密每日成绩单只通过
PushPlus 发送。公开 artifact 仅允许保存不含绝对资产信息的运行诊断。

## 分层账户观察与每日优先级

正式 A/B 只包含 `PRIMARY_PORTFOLIO` 的 14 只核心持仓。父亲账户、本人第二账户和
妹妹账户分别作为 `FAMILY_WATCHLIST`、`SECONDARY_ACCOUNT_WATCH` 与
`SISTER_MANAGED_WATCH` 旁路观察层：它们可复用同一 symbol 的行情、收盘研究和参考
价位，但不会写入 PRIMARY 信号、成交、现金、NAV、回撤、覆盖率或实验天数。
收盘分析按 P0 PRIMARY、P1 父亲、P2 其他已持有账户、P3 候选顺序执行；可选层失败
不会拖累 PRIMARY，重复 symbol 不重复分析。`002759` 在明确成交前始终只是 candidate。

公开代码只保存 symbol、账户层和 held/candidate 状态。第二账户及妹妹账户的真实

或人工复核动作发生实质变化时才发送，并带清晰账户前缀。

旧 `paper_trade_tracker.py` 的 100 万元标准化实验及历史状态继续保留，但正常每日
full 运行不再推进或 Push。只有手动选择 `simulation-summary` 才会查看
“旧版标准化20日模拟实验（非真实持仓A/B）”。

## Level-2 和数据降级

Level-2 只允许使用交易所授权、持牌数据商或用户本人账户已获行情权限的来源。
系统不会绕过付费墙、账户权限、地区限制或服务条款，也不会把普通五档、成交量
或推算结果冒充 Level-2。

无论用户是否上传分时图、K 线、盘口或成交量，系统都应主动查询可获得且带来源、
授权状态和时间戳的数据。数据源按以下顺序增强：合法授权的 Level-2 深度盘口；
新鲜 L1、逐笔、分时与成交量；OHLCV 和技术指标；公告、财务、估值、资金、行业
与政策。Level-2 接入失败不能被静默忽略，报告必须记录失败原因、实际使用的数据
层级和相应置信度折扣。

分钟监控的 Level-2 适配层默认关闭，不会因为检测到 API Key 就自行宣称已获
权限。只有用户已经合法开通数据商权限、对应 provider 明确返回授权结果后，
适配层才逐标的检查：

- provider 身份与授权记录中的 provider 是否一致；
- 授权范围是否覆盖该标的所属 A 股或港股市场，授权检查是否仍新鲜且未过期；
- 数据载荷是否明确声明为 `level2`，普通 L1 即使字段很多也不能通过；
- provider 时间戳是否在允许的新鲜度内，未来时间戳和缺失时间戳都拒绝；
- 买卖两侧是否达到配置的最低深度，价格排序、数量、订单数和买一卖一关系是否
  合理。

任一检查失败都会逐标的记录为 `unauthorized`、`stale`、`incomplete`、
`invalid`、`provider_error` 或 `unavailable`，同时切换到声明式 fallback。
系统继续使用新鲜 L1、合法可得的逐笔、OHLCV/技术指标、公告/基本面、资金、
政策与行业研究，但按失败类别降低候选置信度。Level-2 缺失本身不会阻断已有的
止损风险监控，不过不能成为“主力抢筹、洗盘、诱多”等盘口结论的证据。

接入新的持牌 provider 时，应实现 `scripts.level2_adapter.AuthorizedLevel2Provider`
协议并由可信运行环境注入；provider 自己负责按官方流程鉴权和订阅。不要把账户
凭据写入代码、artifact、报告或日志，也不要通过公共 GitHub runner 连接用户
电脑上的本地行情网关。

没有授权 Level-2 时，系统仍主动使用可获得的新鲜基础行情、OHLCV、成交量、
波动率、支撑压力和估值字段交叉验证，但会明确标记以下限制：

- 无可靠盘口时，不把“抢筹、洗盘、诱多”写成事实；
- 无完整基本面、公告或资金数据时，不输出伪精确上涨概率；
- 数据过期、覆盖不足或来源失败时，停止交易类提醒并保留上一份有效状态；
- PushPlus 失败时保存待发事件，下次运行重试，扫描和模拟记录不会丢失。

| `MARKET_SCAN_SNAPSHOT_PROVIDER_TIMEOUT_SECONDS` | `150` | 单个全市场快照 loader 的硬截止时间；库内无超时请求也不能拖死整轮 |
| `MARKET_SCAN_SNAPSHOT_STAGE_TIMEOUT_SECONDS` | `480` | 单市场快照主备与缓存阶段总预算 |
| `MARKET_SCAN_HISTORY_SYMBOL_TIMEOUT_SECONDS` | `45` | 单只候选历史行情与交易计划调用预算 |
| `MARKET_SCAN_HISTORY_STAGE_TIMEOUT_SECONDS` | `900` | 历史候选批次总预算；耗尽后整轮失败关闭 |
| `MARKET_SCAN_RESEARCH_SYMBOL_TIMEOUT_SECONDS` | `30` | 单只候选非关键研究补证预算；超时只记数据缺口 |
| `MARKET_SCAN_RESEARCH_STAGE_TIMEOUT_SECONDS` | `300` | 最终候选研究补证批次总预算 |
| `MARKET_SCAN_TOTAL_TIMEOUT_SECONDS` | `1800` | 应用层整轮预算（30分钟），必须早于 Actions 75分钟硬超时与盘中迟到边界 |

扫描会把当前阶段、序号/标的、provider、开始时间、耗时、尝试次数、预算、结果和异常类型写入结构化日志，并持续原子更新 `data/market_scan/runtime.json`。单个 provider 或标的超时会进入既有 fallback、数据缺口或安全排除；关键阶段或整轮预算耗尽时主动以失败关闭并保留最后执行上下文，不把缺失数据当成通过。

盘中 `01` 的扫描 watchdog 最多同步等待120秒。当前时段 `02` 仍在运行时记录为 `pending` 后立即结束观察，不阻塞健康的分钟主监控；分钟主监控收尾时只做一次零等待、禁止派发的最终复查。最终取消、超时、失败及产物未就绪分别保留真实 run ID 和故障码，后续成功同步才发送一次恢复通知。

港股实时监控也兼容 Legacy `LONGBRIDGE_APP_KEY`、`LONGBRIDGE_APP_SECRET`、
`LONGBRIDGE_ACCESS_TOKEN` 三件套；OAuth 与 Legacy 均未配置或认证失败时，港股行情
会严格降级并停止交易类建议，不会把腾讯约 15 分钟延迟行情伪装成实时数据。
同一轮遇到瞬时 Longbridge `SessionError` 或连接失效时会丢弃旧 QuoteContext、重建
会话并做一次有界重试；已明确属于无交互 OAuth 认证失败时，本场任务立即熔断重复
重建，后续轮次直接保留严格降级。诊断同时保留外层与根因异常的类型、代码和脱敏
消息。PRIMARY 腾讯批量行情会对未覆盖或陈旧标的改走同提供方备用入口；只有它自己
返回的提供方时间戳也通过 90 秒门槛时才允许作为港股新鲜备用，常见的约15分钟延迟
价仍保持 fail-closed。故障和恢复各只推送一次，详细路由、时间戳、陈旧/缺失及会话
恢复计数保存在验收报告中。

盘中工作流会先恢复 `data/intraday/longbridge_oauth_cache.json.enc`，结束时再把 SDK
可能自动刷新过的 cache 用 `LONGBRIDGE_OAUTH_CACHE_KEY` 加密写回固定状态 artifact；
明文只存在于 runner 的 SDK 私有目录，不进入报告或 artifact。静态 B64 Secret 只作
启动种子，不能在每次 QuoteContext 重建时覆盖更新后的本地 cache；若运维人员更换
B64 种子，其摘要变化会使新种子优先于旧加密状态。未配置至少32字节的独立加密
密钥时，本轮仍可用旧启动种子尝试行情，但保存步骤会明确失败，且不会用不完整状态
覆盖最近有效备份；正式启用前必须配置该密钥。

港股通成员缓存继续保留 840 小时硬上限，刷新全港报价不会延长成员有效期。距离硬
到期 168/72/24 小时时会分级写入报告，并按阈值变化各推送一次维护预警；预警本身
不把健康扫描误判为故障，超过硬上限仍会封锁港股通新候选。

### OAuth 显示 `HK_Basic` / 行情恰好延迟 15 分钟

Longbridge 在 2026-07 修复过一次 OAuth 行情权限绑定问题。服务端修复后，旧 OAuth
缓存不能只等待 refresh token 自动刷新，必须在可交互电脑上重新授权一次。仓库的
辅助脚本会先把旧缓存移动到带时间戳的备份，再打开官方授权流程：

```bash
python -m pip install 'longbridge>=4.0.5,<5'
python scripts/generate_longbridge_oauth_token.py \
  --client-id "$LONGBRIDGE_OAUTH_CLIENT_ID" \
  --force-reauthorize \
  --require-hk-realtime \
  --verify-symbol 700.HK
```

成功输出必须包含港股个股实时包（通常为 `HK_L1_OpenAPI`）；只有 `HK_Basic` 或只有
恒生指数实时包均不通过。随后把新生成的
`~/.longbridge/openapi/tokens/<client_id>` 重新 base64 编码，覆盖 GitHub
Environment `STOCK_LIST` 中原有的 `LONGBRIDGE_OAUTH_TOKEN_CACHE_B64` Secret。
首次启用跨运行刷新持久化时，再创建独立的
`LONGBRIDGE_OAUTH_CACHE_KEY` Secret，例如使用密码管理器生成至少32字节随机值；
不要复用 OAuth token、PushPlus token 或模型 API key。
Linux 可执行：

```bash
LB_TOKEN_CACHE="$HOME/.longbridge/openapi/tokens/$LONGBRIDGE_OAUTH_CLIENT_ID"
base64 -w 0 "$LB_TOKEN_CACHE"
```

macOS 可执行 `base64 < "$LB_TOKEN_CACHE" | tr -d '\n'`。不要把输出写入仓库、
日志或 artifact。更新 Secret 后，先手动运行
`Longbridge 港股实时行情只读预检`：`permission` 模式可在午休/休市时验证权限包；
`live` 模式须在港股连续交易时段运行，并要求每只测试标的的提供方时间戳不超过
配置的新鲜度阈值。两个模式都不会发送 PushPlus。

如果强制重新授权后仍只有 `HK_Basic`，再到 Longbridge Developer Center 检查
OpenAPI（不是 App/PC/Web）的港股行情权限；账户确有实时包却未下发时，应把
`quote_package_details()` 的非敏感包名和 member ID 私下提供给 Longbridge 支持，
而不是通过调大 `INTRADAY_QUOTE_FRESHNESS_SECONDS` 绕过。

模型密钥和 PushPlus Token 使用既有 `LLM_DASHSCOPE_API_KEY`、
`LLM_DEEPSEEK_API_KEY` 与 `PUSHPLUS_TOKEN` secrets。停用新增能力时，在
GitHub Actions 页面分别 Disable `01-intraday-session.yml` 和
`03-intraday-supervisor.yml`，并按需 Disable `02-market-scan.yml`；原有 20 日模拟仍可
独立继续。


### 持仓参考位恢复与诊断

`01` 恢复收盘缓存后先执行 `reference_levels_audit.py`，按原七天有效期和信号显式过期时间核验 PRIMARY。覆盖不完整时仍检查同分支近期 `paper-close-state` 备份；数据库存在或 SQLite 完整性通过均不代表参考位有效。`reference_restore_before.json` / `reference_restore_after.json` 与会话 `reference_levels.by_symbol` 记录来源、最近日期、有效来源及缺失原因；未覆盖止损或目标的能力逐项标明。港股短代码如 `1548.HK` 与 `HK01548` 使用同一映射。

未来日期、过期、未注明日期、非分析或非 active 信号均不能成为持仓参考位。若上游收盘分析没有生成新的有效计划，盘中仍保持参考位降级，不能把旧计划重新启用；正常收盘分析与新备份的生产验证仍是恢复覆盖的必要条件。

若 `analysis_history.id` 已由分析信号的 `source_report_id` 关联，历史参考位必须同时满足关联信号的原有状态和显式 `expires_at`，不能因历史记录仍在七天窗口内而恢复过期/失效计划。单次监控、持续盘中会话和恢复审计使用同一关联护栏；未导出关联信号的旧版历史仍按原有日期门禁处理。`linked_signal_ineligible` 表示历史回退已被关联信号的有效性拦截，不会延长有效期或伪造休市日计划。

`check_intraday_integrations.py --calendar-report reports/market_session_gate.json` 使用本次会话开始日的交易日历证据。只有确认港股休市、日历未降级且本次未请求港股行情/轮次时，港股实时权限及轮次项才标记为不适用；缺失、跨日期或降级的证据不能豁免检查，A股行情降级、落盘和推送失败仍使验收失败。

腾讯 A 股全市场备用返回原始 `zxj`/`zdf`/`turnover` 等字段时，先转换为统一快照：成交额由万元换算为元，市值由亿元换算为元，成交量保持与东财一致的手。字段缺失或数值无法解析仍按原覆盖门槛拒绝该提供方；这只修复字段适配，不保证上游接口持续可用。

港股官方 PDF 常将五位股票代码省略前导零，且繁体公司名称可能不同于快照简称。正文读取器可识别页首有界范围内的独立短代码行（含 PDF 字体损坏的外围标签），不将正文金额、价格、日期或其他长代码当作身份。原索引的股票/日期校验、HTTPS 来源、大小、无重定向、最低正文长度和摘录限制保持；取得摘录不等于全文审查。

### 模型关键数值一致性

“占成交额6.29%”是比例描述，不与以元计的快照成交额比较；仅明确占比语境且紧随百分号、没有货币单位的描述按此区分。该区分不代表比例或新闻事实已经核实，也不豁免结构化 `numeric_facts`、同句绝对成交额、PE或其他数值冲突，数值容差和交易安全门保持不变。

文字数值的标准千位逗号必须完整解析，例如`成交额1,199,779,572HKD`不能截为1；错误分组仍拒绝，原单位、币种、精度和结构化回显校验不变。数值冲突诊断增加`text_field`和`claim_context`（命中前后各最多120字符），用于检查原句的日期与比较语境；记录语境不代表历史数值已经核实，也不会自动绕过冲突。旧产物只保留匹配片段时，不能据此断言是模型算错还是日期语境误判。

扫描提示提供确定性 `numeric_fact_contract`，`change_pct=0.27972` 表示0.27972%，价格和成交额明确 CNY/HKD。实际模型请求必须回传 `numeric_facts`，校验缺失值、数值、币种以及直接标注的快照价格/日涨跌幅/成交额描述（含风险与推断文本）。结构化回显保持原精度校验；文字摘要按实际显示精度舍入，科学计数法先完整换算，“日涨跌幅/日内涨跌幅/日涨跌”保留数字原符号，只有明确“日跌/跌幅”才表示下降。缺失PE/PB列于`nullable_missing_fields`，可省略或回传null，但数字、0和字符串占位均不能冒充来源，文字也不得补造无来源的PE/PB；已提供字段的null仍不通过。数值矛盾使用既有批次重试/备用及总预算；仍失败时完整性不通过。服务注入路径同样检查矛盾并阻止受影响候选进入条件共识，保留原始意见及逐字段诊断，报告不把错误数字静默修正成有效结论。该检查不能声称验证了任意自然语言事实。文字舍入不替换交易门禁使用的原始输入，不改变筛选、价格区、仓位规则或参考位有效期。


### 收盘分析跨午夜的归属日

`00` 使用原始 Actions run 的 `created_at` 与固定18:00定时槽解析收盘日，允许任务
在当天18:00至次日09:00之间完成。平台在次日凌晨才创建的定时任务仍归属前一天；
读取原始创建时间而非重跑开始时间，旧 run 不会被重跑成今天的任务。解析后还必须
留出完整 job 时间预算；每个分析批次有开盘前硬截止，日历读取失败、未知 cron、
周末槽位、过期 run 和预算不足均拒绝。无需新增仓库变量、授权或外部触发器。

个股批次传入 `main.py --close-analysis-date YYYY-MM-DD`，仅此收盘路径按目标日
严格读取A/H交易日历，并把目标日18:00作为既有pipeline的冻结参考时间。
此路径禁用实时报价替换日线；行情查询上界设为归属日的次日，以覆盖Yahoo的右开
结束日期；返回数据在入库前严格裁剪至归属日，数据库上下文也截于归属日。缺少该日日线
时拒绝生成分析，避免凌晨补出次日虚拟K线。配置副本仅作用于本轮收盘任务。普通CLI、
Docker、API和定时服务入口未传该参数时行为保持；它不是历史补跑或跳过安全门的入口。
交易日检查关闭或`--force-run`也不能在此路径把休市市场变为开市。

PRIMARY覆盖审计要求归属日开市的全部标的100%覆盖；A/H同时开市仍为14只，
单一市场休市时记录`closed_primary`并审计开市标的，两边休市则不生成新分析。
`--require-dated-close`要求`stock_daily`存在完全同日的收盘价，不接受未注明日期的
实时/报告备用价格来充当收盘覆盖；分析`raw_result.close_analysis_date`也必须同日，
不能仅因有同日价格就接受另一天的分析。新分析按真实生成时刻保存，`--analysis-since`
仍仅接受本轮开始后的记录，不伪造`created_at`来填旧日期。

报告artifact增加`data/daily_analysis/close_context.json`和`run_metadata.json`，记录归属日、
原始创建时间、观察时刻、截止时刻与开市/休市PRIMARY。持仓参考位七天有效期、
显式expiry、行情新鲜度与全部交易阈值保持；休市或未生成有效新计划时继续明确降级。
本修复不改变GitHub平台延迟，也不手动补跑生产任务或发送测试推送。大盘复盘保持
独立的当前时刻路径，不作为个股参考位覆盖的证据。

收盘扫描兜底安装已有交易日历依赖，并复用收盘归属日解析器读取原始run创建时间。
只在原归属日19:27至21:00检查或派发扫描；原日21:00后安全跳过。跨午夜延迟启动
不会等待下一日19:27，也不会派发下一日扫描；等待期间跨过截止也同样跳过。
超出收盘归属日解析窗口的旧run继续拒绝。
兜底artifact保留原始run元数据和检查结果，不改变上午、下午盘中兜底的现有规则。
